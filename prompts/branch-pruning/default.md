# 分支价值判断

你刚刚完成了一个函数的污点传播分析，识别出了若干跟入点（followup）。
所有跟入点都有污点数据流入，现在需要你判断跟入后是否有较大概率
发现有价值的漏洞。

## 背景

这是嵌入式/网络设备的安全审计。设备管理面代码（HA 主备切换、订阅管理、
Timer 事件、状态机转换、配置下发）是攻击者通过网络协议可触达的高价值
攻击面，这些代码逻辑复杂、边界条件多，恰恰是最容易出漏洞的地方。

## 判断标准

**pursue=false（不跟入）**——仅当明确是以下死路之一：
- 纯日志/打印函数：污点仅用于格式化输出字符串，不参与控制流或内存操作
- 纯透传 wrapper：函数体只是把参数原样转发给另一个函数，自身无任何逻辑
- 立即完全清洗：污点进入后第一件事就是被强校验拦截，后续只使用安全值

**pursue=true（跟入）**——以上死路之外的所有情况，包括但不限于：
- HA/订阅/Timer/配置管理等设备管理面代码（高价值攻击面）
- 函数可能将污点用于内存操作（索引、大小、地址、拷贝）
- 函数有复杂逻辑（状态机、多分支、错误处理）
- 函数交互硬件/特权操作
- 不确定时默认 pursue=true

## 注意

- 不要根据函数名中的关键字（Subscribe/Timer/HA 等）猜测是否值得追踪
- 判断依据是：跟入后能否发现漏洞，不是函数属于哪个类别
- 你已经分析过当前函数，了解每个 callee 的调用上下文
- 如果拿不准，pursue=true

## 输出格式

```json
{
  "decisions": [
    {"function": "FuncA", "pursue": true, "reason": "HA订阅函数接收含污点PID的结构体，可能将PID用于socket操作或状态查询"},
    {"function": "FuncB", "pursue": false, "reason": "纯日志函数，污点仅作为格式化参数"}
  ]
}
```

- `function`：跟入点的函数名，与输入列表中的完全一致
- `pursue`：布尔值，true=跟入，false=不跟入
- `reason`：简短的中文判断理由
