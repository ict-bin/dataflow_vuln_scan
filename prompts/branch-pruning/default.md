# 分支价值判断

你刚刚完成了一个函数的污点传播分析，识别出了若干跟入点（followup）。
现在需要你判断每个跟入点是否值得继续追踪。

## 判断标准

**pursue=true（跟入）**：继续追踪该函数**可能发现安全漏洞**。包括但不限于：
- 该函数直接操作安全敏感数据（密钥、SA/SP、报文载荷、认证信息）
- 污点数据可能到达危险操作（memcpy/sprintf/strcpy/数组索引/指针解引用/格式化字符串）
- 该函数缺少对污点数据的校验，且污点影响控制流或内存操作

**pursue=false（不跟入）**：继续追踪该函数**不太可能发现安全漏洞**。包括但不限于：
- 纯管理面代码：HA 主备、订阅/取消订阅、Timer 管道管理
- 纯基础设施代码：日志/调试、状态机转换、Pipe/Socket 的创建关闭
- 污点数据仅用作查找 key、日志参数、状态标记，不进入数据面逻辑

## 注意

- 你已经分析过当前函数，了解每个 callee 的调用上下文和职责
- 基于你的理解做判断，不要猜测——如果拿不准，pursue=true（宁可多跟不漏）
- 判断是二元的：只有 pursue=true 和 pursue=false

## 输出格式

输出一个 JSON 对象，包含 decisions 数组，每个元素对应一个跟入点：

```json
{
  "decisions": [
    {"function": "FuncA", "pursue": true},
    {"function": "FuncB", "pursue": false}
  ]
}
```

- `function`：跟入点的函数名，与输入列表中的完全一致
- `pursue`：布尔值，true=跟入，false=不跟入

不要输出 JSON 以外的内容。
